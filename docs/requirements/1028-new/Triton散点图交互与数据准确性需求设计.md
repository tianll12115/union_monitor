## 4. 指标与关联契约

### 4.1 粒度、E2E与颜色

主键为`(repository, run_id, attempt)`；一个E2E散点对应一次Integration Tests run/attempt，PR不是主键，SHA也不是触发主键。首次运行的E2E：`max(有效且非skipped job.completed_at) - workflow.created_at`。并行job不相加，`updated_at`不得代替结束证据。缺少完整分页/完成时间、时间倒置或身份不明不纳入完成分位数；重跑前置排队起点未知时仅展示观测时长。整套跨workflow门禁仍未确定；新增卡片成员不改变E2E时长或KPI分母。

绿色/红色依据该散点自身run/attempt的规范化结果，不依据PR最终合入状态，不以同PR其他提交失败覆盖成功点。`success`绿色`#25724b`，`failure/timed_out/action_required/startup_failure`规范化为失败红色`#bf4038`；执行中/排队蓝色，取消琥珀色，未知灰色，均有文字/可访问名称。NPU图依据其自身记录的状态，不借用另一次Integration Tests状态。

### 4.2 workflow与job时间

| 字段/标签 | 公式与条件 | 注意 |
|---|---|---|
| workflow“首任务等待” | `min(非skipped有效job.started_at) - attempt_origin` | 用户所需workflow排队的操作性定义，包含调度/准备至首任务真正开始；不是单独runner排队。首次origin=workflow.created_at；重跑origin无可靠排队起点则本字段留空。 |
| workflow“执行跨度” | `max(有效job.completed_at) - min(有效job.started_at)` | 墙钟跨度，包含执行阶段内部调度等待；并行不相加；不是CPU/GPU占用时间。要求job分页完整且完成。 |
| workflow E2E | 首次运行的上述等待＋执行跨度 | 必须与散点E2E一致；若缺证据则均明确留空/部分，不能猜。可靠集合其他workflow只各自统计，不累加成主点E2E。 |
| job“排队” | `job.started_at - job.created_at` | 同一job/attempt源时间戳完整且有序；不能用workflow.created_at冒充job.created_at。 |
| job“执行” | `job.completed_at - job.started_at` | 保留零值和小数；源异常留空且提示，禁止max(0,负数)静默归零。 |
| 执行中 | `as_of - start`仅可标为“截至采集已观测” | 不与完整时长混合，不计完成分位数。尚未开始的job执行为空，排队可按可靠job.created_at算观测值。 |

所有内部和导出数值单位秒；显示分钟两位小数，旁边展示精确秒或毫秒。`0`=确实零，`null`=未知/不适用，失败≠耗时缺失。UTC存储、上海时间显示，包含日期和秒；跨日和>24小时不省略日期。`run_started_at`可作为单独来源字段披露，不与首job开始或job创建混用。

### 4.3 可靠关联与“同提交其他运行”

可靠关联必须携带可核查证据：显式记录的父run/attempt与`workflow_run`触发链、共享不可变触发标识及其采集证据，或可证明同一次调用的父子workflow关系。仅同PR/SHA、同event名、同actor、相邻时间、同run_number均不够。关联链须验证仓库、PR和SHA身份；出现冲突则不归组并提示。可重用workflow如果在GitHub表现为同一run中的jobs，按该run的jobs展示，不虚构独立workflow run。

当前schema没有上述关系，默认本次集合仅当前Integration Tests run/attempt，卡片明确“未采集到其他可靠关联workflow”；不写“本次只有1个workflow”暗示全量已知。其他集合使用`repo + 已验证PR + 完整SHA`找当前快照内候选，排除本次集合，以`run_id+attempt`去重。不同PR即使共享SHA不得串联；同一run的其他attempt归“其他运行”，不自动成为本次。候选缺失PR或SHA无法可靠归属时不猜。

卡片本次的可靠成员可在当前选区外，但必须标“选区外来源”；同提交其他运行也可以读取整个当前快照并标注其范围，**均不参与悬停高亮集合或改变当前图指标**。快照边界外不宣称完整，不因候选0条宣称该提交从未触发其他workflow。

## 5. 详细需求与验收标准

### TS28-001 丰富悬停与来源入口（P1）

- AC1：悬停E2E点立即进入预展示，建议100ms内稳定展示PR号/标题/作者/分支、完整SHA可复制、run ID、attempt、触发日期、状态、E2E与资格原因；未知身份显示“未关联PR”，没有伪造PR链接。
- AC2：卡片有真实PR链接、本次run/attempt Actions链接及“运行详情”入口。跳转保留attempt，`target=_blank`链接具备`rel=noopener`，用户文本转义，危险scheme不渲染为可点链接。
- AC3：鼠标移入卡片内容不消失；离开点与卡片后180ms关闭；点切换时内容与源点同步，取消旧定时器，快速横移不显示旧PR。
- AC4：卡片最大宽建议640px，宽度不超过视口减24px；高度不超过视口减24px，内部滚动；翻转定位不遮原点，不超出屏幕，长标题/长job名换行。390/768/1440/2560宽及短高度验收。
- AC5：Tab聚焦散点能够获得同一信息；可键盘进入卡片链接，Escape关闭并返回原触发点。交互卡片用具名非模态region/popover语义，不能使用不允许交互控件的纯tooltip语义代替。
- AC6：双图适用范围、NPU辅助运行的E2E不适用状态和pin优先级严格按第3.2节，测试固定身份不会被跨图hover改写，显式切换/解除/筛选均清理高亮。

### TS28-002 本次workflow及其他运行明细（P1）

- AC1：每条可靠成员显示workflow名称、run ID/attempt、触发时间、首任务等待/执行跨度精确值、状态和对应Actions链接，缺字段明确解释。
- AC2：“同提交其他运行”单独分区，醒目标“不计E2E、不能证明同次触发”；列齐候选、独立耗时及链接，不影响主点时长。严格执行第4.3节身份边界。
- AC3：每个workflow可展开全部jobs，每job列排队/执行/状态/来源。分页不完整明确“部分明细”，禁止暗示全量、按前100条推导完整结束时间。
- AC4：并行workflow/jobs、同SHA多次独立触发、跨日晚标签、attempt2、可重用workflow、无法归属PR和关系冲突均有用例；新字段缺失时安全退化为当前单run证据。

### TS28-003 A3/A5重点任务（P1）

- AC1：默认突出A3 py3.10、A3 py3.11、A5 py3.12，并列出可靠集合中实际发现的其他A3/A5矩阵，不因为Python版本不同而遗漏。兼容aarch64/amd64 runner名称；完整job名、架构、Python版本仍可辨识。
- AC2：每条显示排队和执行的分钟与精确值、结果、job链接；任务按`repo/run/attempt/job_id`去重。同类多个job不能只取首条、拼接不同attempt或用其他workflow的成功任务覆盖当前失败。
- AC3：重点任务来自“本次可靠集合”；同提交其他运行中的A3/A5只在其所属分区列出，不冒充本次。未触发/被跳过、明细采集失败、没有找到匹配任务三者区分。
- AC4：0、100ms、600ms、null、倒置时间、排队中/执行中/取消/失败与矩阵扩展均有断言。

### TS28-004 结果颜色（P1）

- AC1：所有成功点为绿色、失败点为红色，按第4.1节映射。真实浏览器断言`.dot`的computed fill，不仅断言fill属性中的CSS变量字符串。
- AC2：悬停/高亮/重绘/筛选/详情开关后颜色不变，图例与卡片状态一致；未知结果不得默认绿色。

### TS28-005 当前选区同PR高亮（P1）

- AC1：hover/focus到PR=P的点，两张图各自**当前已绘制**且PR=P的所有点（所有SHA和attempt）半径从3.5增至7 CSS px；当前点可加1.5px同色描边。不重新计算x/y、不移动真实坐标、不添加连接线；非同PR保持原大小和颜色。
- AC2：集合为“当前分支×时间窗×该图状态条件×该图可绘条件”；列表搜索沿用现有仅影响列表的契约，不隐式改变图。选区外、筛选隐藏点、另一PR同SHA、未知PR点都不能加入；PR未知只放大自身，不把所有null PR组成一组。
- AC3：移入卡片期间保持该组；离开点与卡片、Escape关闭、数据重载或切换项目后恢复。切换到另一点立即按新PR计算；resize只重新投影并重用当前有效PR，不能留下旧DOM标记。
- AC4：高亮不改变KPI、轴范围、结果计数、列表、URL筛选条件或导出ID集合；不能把PR历史的全快照数据灌回当前选区。
- AC5：放大不改变基础命中范围和选点结果；完全重叠点沿用已有候选选择器，每条run仍可查看。先绘普通点再绘高亮层可提高可见性，但保持稳定身份和键盘焦点。半径按CSS像素验收，SVG缩放后也不能忽大忽小。

### TS28-006 移除桶中位数（P2）

- AC1：E2E与NPU主图均移除六小时桶中位数曲线、文字、title、图例和相关分桶计算/失效样式引用。
- AC2：保留图内P90参考线及其明确标签、顶部P50/P90和统计卡片中的整体P50；“取消桶中位数”不等于取消所有中位数统计。
- AC3：无样本/单点/密集图/状态筛选后，DOM无`.median-line`或桶中位数文案；实际截图无残留曲线。禁止仅CSS隐藏而继续计算、保留空图例。

### TS28-007 准确性与可追溯（P1）

- AC1：从GitHub原始run/attempt/jobs独立推导时间，逐字段与payload、卡片、详情、图坐标及下载对账；不能复用生产计算函数作为唯一oracle。
- AC2：每个计时字段保留起终时间、来源字段、来源URL、精确单位、观测截止及资格/缺失原因；验证URL仓库/run/attempt/job身份一致，缺证据fail closed。
- AC3：完整采集账本解释raw→去重→排除→发布的每条差值；无可靠证据不宣称全部workflow、完整PR提交或最新全量。
- AC4：冻结PR2280基准始终1536秒；加入两天后Auto labeling不改变E2E。选区内最长4554秒、失败2594秒样本及四个上游样本保留回归。

### TS28-008 范围、导出与旧需求兼容（P1）

- AC1：合法多branch URL不出现“只保留首个值”假警告；两分支集合和无branch全量都可解释。
- AC2：CSV/资格JSON同集合同口径，包含metric版本、选择窗口、branch、query、未知时间豁免、发现截止、采集完成及边界说明；零行导出也带scope。
- AC3：无效/过期详情链接有明确提示；缺失、无样本、无匹配、网络失败分别处理；保留冷启动详情和统一关闭状态清理。

### TS28-009 交互性能与生命周期（P2）

- AC1：hover不发逐点GitHub请求；数据来自当前已加载快照。按`repo+PR`预建索引，只修改可见组半径/class；同一PR点间移动不全图重绘。
- AC2：以本次2950条全快照、110/133可见点及合成1000点单图压测：mousemove到组更新目标p95≤50ms，记录机器/浏览器/采样次数；超标作为需优化证据，不伪造测量。
- AC3：定时器、监听器、索引和hover状态绑定渲染session，切换项目/数据后清理；卡片不引用前次payload对象；reduced-motion下无尺寸动画。

### TS28-010 PR与发布门禁（P1）

- AC1：全量Python、Node、真实浏览器套件全部执行；固定输入先准备，关键一致性测试不能因无本地快照跳过。新增/修改可执行代码相对main行覆盖率>80%，保存当前提交覆盖证据。
- AC2：自动执行下节矩阵和负例变异。当前提交4个前置job及Dashboard quality gate全绿后方可PR合入，分支保护保持；不允许只补文案测试、裁剪套件或使用旧提交绿灯。
- AC3：发布后verify绑定数据/资格清单指纹，再检查实际页面新脚本、真实点与来源；发布成功和功能验收分别记录。

建议新增只读展示适配层，避免把复杂拼接分散到E2E/NPU两个tip函数。保留当前schema v2数值兼容，新增可选字段先有来源证据再填：

## 7. 验收矩阵与能拦截的故障

| 测试层 | 必跑场景 | 独立断言/故障注入 |
|---|---|---|
| UT：关联 | 同PR多SHA；同SHA独立run；不同PR同SHA；null PR；attempt2；可靠父子链/冲突 | 精确成员ID集合，错误按SHA归组必须失败；辅助运行不延长E2E。 |
| UT：计时 | 串/并行jobs、skipped、分页不完整、缺时戳、负数、零、小数、跨日、执行中 | 用固定源时间独立相减；反转时戳/用updated_at/求和并行时长必须失败。 |
| UT：展示适配 | A3/A5多矩阵/多workflow/多attempt/重复任务 | 完整身份和精确值，不用其他分区任务填当前缺口；恶意标题与链接安全。 |
| 浏览器：hover | 点→卡片→PR/Actions、快速换点、移出/重入、触摸、键盘、Escape | 实际内容身份、链接、滚动与可访问性；无空卡、无过期计时器覆盖。 |
| 浏览器：同PR | 2个SHA+同SHA重跑，另一PR同SHA，隐藏状态/窗外/分支外点 | 点半径确实变7，cx/cy及computed fill不变；可见成员精确匹配；移出恢复；URL/KPI/下载无变化。 |
| 浏览器：颜色 | 成功/失败/超时/取消/执行中/未知；hover后重绘 | computed fill与图例状态一致，强制失败点绿色变异必须失败。 |
| 浏览器：参考线 | 双图、0/1/密集样本、筛选后 | 无桶中位数DOM/图例/图形，P90与总体P50保留；重新注入曲线必须失败。 |
| 浏览器：几何 | 390/768/1440/2560、字体加载、短视口、容器变宽、长标题/长尾 | 相对真实裁切祖先边界检查，屏幕线性逆算≤1px，实际截图复核。 |
| 下载/门禁 | 非零、零、未知时间、多branch+query、采集边界 | 真正读取CSV/JSON并与页面集合/metric核对；旧metric变异必须失败。 |
| 发布 | 当前SHA/数据fingerprint/资格hash；API失败/数据schema过旧 | fail closed且页面说明旧数据，不把来源故障展示为真实零。 |

每个TS28需求都有至少一条真实行为验收；源码regex不能充当唯一oracle。完整密集回放需以冻结数据做源值→坐标→屏幕三方核验。验收报告分开列“需求已实现”“当前提交CI通过”“线上已验收”，未观察到的项目写未验证。
