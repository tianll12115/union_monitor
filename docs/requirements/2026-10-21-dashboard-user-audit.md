# 统一看板使用者审计与整改需求（2026-10-21）

本文交付审计结论、需求要求与验收标准；未修改看板业务实现，所有业务需求均为待实施或待验收。文档校验通过不等于业务验收通过。

## 1. 审计结论与适用范围

当前看板需要整改。最影响使用判断的是：UBS 默认列表粒度与用户预期相反、列表标示的排序与实际顺序不符，以及用户无法直接区分 Triton 当天新增 PR、涉及 PR、提交批次和快照截止后的新增记录。

- **#1627 不是源数据中的同一执行被重复存储。** 用户提供的窗口内，ubs-engine 有 36 个 PR、107 个不同批次；#1627 有 9 次不同执行。当前入口默认按批次展示，因此这个 PR 被展示 9 行。新要求是默认一个 PR 一行，以最长合格 E2E 批次为代表，9 次执行保留在详情。
- **Triton 当天数据偏少，已证实存在快照时间差；尚无证据证明少了多少应采记录。** 本轮公开快照截止北京时间 17:03:40，采集完成于 17:17:34。当天至该截止有 45 个批次、22 个涉及 PR；源站当天至该截止新建的 7 个 PR 全部在快照中。约 20:53 抓取的源站当天新建 PR 为 14 个，另外 7 个均晚于快照截止，不能据此报“漏采 7 个”。所有分支与 main/main-dev 的数量不能混用。
- **散点图贴边纳入整改，视觉验收仍需实测。** 用户已明确反馈；当前实现固定左边距 50px，长耗时刻度包含完整 `min` 单位，移动端图容器左右仅 4px。线上 DOM 出现 `1876.63 min` 等长标签。浏览器截图连续超时，本轮没有获得可审阅截图，因此不把具体裁切像素、重叠数量或所有宽度表现写成已确认事实。

审计时间：2026-10-21 北京时间约 20:35–21:00；数据抓取时刻以证据文件为准。实现基线为本地 `9ea020f`，线上行为另以本轮 DOM 和公开 JSON 为准。本次覆盖 UBS 单仓记录/详情/搜索/排序、跨仓入口、Triton 概览/趋势/公共记录、工作台、路由、错误与空数据、导出、键盘入口，以及公开数据与源 API 的定点核对。未穷举九仓全部 PR、全部设备、全部源 API 历史分页或所有故障组合；“所有问题”指本次范围内识别的问题，不能保证未知缺陷为零。

本次仅新增本文、审计证据与文档测试；不触发生产采集、不改分支保护、不部署、不合入 main。源码修复、线上验收与合入应另行实施。

## 4. PR 列表、代表记录与详情

### UAR-001：默认 PR 列表去重

**问题与影响：** E01/E02。当前 `web/app.js:4,29–31` 默认 `entity=batches`，#1627 分散在多页，用户容易误认有多个 PR，难以比较最慢 PR。数据本身的批次 URL 没有重复。

**需求要求：** UBS 的 PR 入口及未指定实体的旧链接默认 PR 视图。以项目、源实例、完整仓库、PR 编号为身份，一 PR 一行；行中展示代表 E2E、代表批次编号/结果和执行总次数。全部执行通过详情查看；若保留专家批次入口，必须由用户明确切换并标为执行批次，不改变默认 PR 列表。

**验收标准：**
- UAR-001-AC01：加载 E02 固定样本并遍历全部分页，恰有 36 行、36 个不同 PR，#1627 仅 1 行；切换页长 15/30/50 不增减集合。
- UAR-001-AC02：同号异仓、异源 PR 各保留一行；重新加载和直接打开用户原链接仍默认 PR，不能靠搜索 #1627 或手动选 PR 才满足。

**测试设计：** 冻结 36 PR/107 批次样本做真实浏览器默认入口与全分页断言；另加同号异仓 fixture。更新锁定旧默认的 `tests/browser/unified-records.spec.cjs`，保留显式批次入口测试。

### UAR-002：最长代表与全部执行可核对

**问题与影响：** E02。现有 PR 模式已有正确代表算法，应复用并向用户解释，避免只去重后取第一条或最新条而改变指标。

**需求要求：** 在当前数据覆盖内，对 PR 的合格、有限、非负 E2E 批次取最大值；并列保持 trigger 编号、URL 的既有稳定规则。失败批次可作为代表，取消按 UBS 既有资格处理，不按成功偏好筛掉。行内任务指标来自同一代表批次。无合格 E2E 时显示未知及原因，合法零值保留。详情列出全部已采集执行，并说明“当前覆盖内”与“全生命周期”区别。

**验收标准：**
- UAR-002-AC01：#1627 行显示 #7604、997459ms 对应的两位分钟值 16.62；详情可定位全部 9 个不同 trigger、45 个子任务，标识代表且不丢失失败/重跑。
- UAR-002-AC02：构造最新不最长、失败最长、并列、合法零、缺值/无穷/负值和全部不合格样本；代表、关联任务、列表/KPI/导出一致，未知不补零，显示精度不改变比较结果。

**测试设计：** 补 `tests/test_representative.py`、`tests/records.test.cjs` 到真实默认 PR 行与详情；逐条比对输入身份和代表字段，不能仅检查渲染了一个编号。

### UAR-003：修复列表排序、实体切换与分页

**问题与影响：** E01 首屏 15.81、16.17、15.90…并非降序，页面仍写 E2E 从长到短。`render()` 在 `renderEntityChrome()` 更新选项前构造列表，初始 PR 排序值可能被误用到批次字段。同页从批次导航到 `entity=prs&sort=batches` 还会因旧 select 选项丢失排序。`web/records.js:39–51` 将 start_at 当数值，ISO 时间也需规范化。

**需求要求：** 先确定实体、合法排序键与字段，再排序完整集合、后分页。日期支持契约定义的毫秒与 ISO 字符串；未知最后，合法零有效，并列稳定。选中项、说明、URL 和实际行序一致。

**验收标准：**
- UAR-003-AC01：全部页拼接后 E2E/排队按数值非递增、开始时间按真实时间非递增；第一行是全集最大值，输入顺序改变不影响结果，缺值末置。
- UAR-003-AC02：在同一标签页反复切 PR/批次，按批次数排序，再前进/后退/刷新/打开分享链接，选择和行序一致；更改页长不重排集合。

**测试设计：** 增加真实 select 的整页测试，覆盖冷启动和已渲染另一实体两条路径；跨天 ISO 时间不能用字面编号顺序充当时间验收。

### UAR-004：排队列读取真实证据

**问题与影响：** E02。107 批次的顶层 `queue_ms` 均缺失，`trigger.queue_ms` 有值；`web/records.js` 读顶层字段，导致用户看到全部“—”，排队排序失去意义。

**需求要求：** 定义公共批次排队字段的来源与单位，规范化时读取实际 trigger 排队证据；若含其他分项，按当前 UBS waiting+blocked+buildable 定义，不把任务最大排队与 trigger 排队混为同一指标。确实缺证据才显示未知。

**验收标准：**
- UAR-004-AC01：E02 样本中有有效 trigger.queue_ms 的行显示对应分钟值，详情/排序/导出可对照源毫秒；不是107行全部未知。
- UAR-004-AC02：合法0显示0、缺字段/异常值显示未知与原因；不同排队定义在字段与说明中可区分，不凭空合计。

**测试设计：** 用真实形状 `{trigger:{queue_ms:…}}` 和缺值样本覆盖规范化、排序及页面，避免只测人为带顶层 queue_ms 的 fixture。

### UAR-005：搜索承诺与分析范围一致

**问题与影响：** E02/E05。默认批次搜索只匹配 PR/标题/batch_id，输入框却承诺作者/SHA；`hw-sgl` 在 PR 模式匹配4个 PR、批次模式0，`0524f587` 在 PR 模式命中#1627、批次模式0。

**需求要求：** 两种实体均支持标示的编号、标题、作者、完整/短 SHA；匹配 PR 属性时返回它在当前范围内的对应行。搜索只定位列表与导出，分析集合的 KPI/趋势保持既定语义，并在搜索附近明示该范围。

**验收标准：**
- UAR-005-AC01：上述两个真实查询在 PR 模式分别匹配4个PR、1个#1627；显式批次模式可查到相关执行；大小写/空白处理规则明确，清空恢复原集合。
- UAR-005-AC02：搜索前后 KPI/趋势不因列表搜索变化，结果数/分页/导出与列表一致；零匹配有清除操作，不能宣称项目无数据。

**测试设计：** 补完整页面 PR/批次搜索对照及搜索后导出，输入真实 author/SHA 字段而非把关键词偷偷放标题。

### UAR-006：点击哪次执行就打开哪次执行

**问题与影响：** E05。`renderBatchTable()` 存在 data-batch，但 onclick 只传 PR；点击非代表批次可能展开另一次执行，排障对象被替换。

**需求要求：** 批次入口向详情传完整稳定身份；显式选中优先于代表默认。PR 行默认打开代表，同时可选择其余执行；不能只靠 PR 编号或裸 SHA 匹配。

**验收标准：**
- UAR-006-AC01：点击#1627的#7589时详情选中#7589；从PR行进入默认#7604；9次之间切换时标题、结果、任务和来源链接同步。
- UAR-006-AC02：异仓同号、同SHA不同attempt、已失效批次链接不会打开另一个批次；不存在时给出可返回的明确提示。

**测试设计：** 同一 PR 至少两批且代表不是被点击批，真实点击表格后断言展开身份和来源 URL。

### UAR-007：详情开关与地址双向同步

**问题与影响：** E05。Escape关闭只清内部对象、URL仍有pr；同仓路由去掉pr又不关闭已开dialog。用户后退或刷新会遇到意外详情。

**需求要求：** 详情可从地址重建，关闭/遮罩/Escape/后退均同步状态；地址无pr则关闭，地址有有效pr与batch则打开对应详情。关闭后恢复原列表焦点与位置。

**验收标准：**
- UAR-007-AC01：依次打开、Escape关闭、刷新，详情不重开；打开后浏览器后退到无pr地址即关闭，前进能恢复。
- UAR-007-AC02：关闭按钮、遮罩、跨仓切换和无效pr/batch路径均无残留滚动锁、浮层、旧任务内容；列表筛选/页码保持有效。

**测试设计：** 补真实dialog cancel/close及浏览器历史测试，不能仅直接调用关闭按钮的函数。

## 5. 筛选、图表与当天数据

### UAR-008：筛选状态完整恢复与清除

**问题与影响：** E05。`applyProjectRoute()` 只设置出现的参数，先进入q/state/ps/page链接、再进入无参数链接，旧值仍保留；“清除高级条件”未同步URL。控件、分享地址和结果可能互相矛盾。

**需求要求：** 每次路由从明确默认值构建完整状态；参数缺失/非法值不继承另一路由残留。所有筛选、清除、重置、排序和分页经同一状态更新路径同步URL，越界页码规范化。

**验收标准：**
- UAR-008-AC01：从q=needle/state=merged/ps=50/page=3返回无条件入口，恢复约定默认搜索、状态、页长和页码，结果与新标签页相同。
- UAR-008-AC02：点“清除高级条件”后URL去掉state/tf/qf；复制到新页、前进后退与屏幕相同；非法/重复参数给出明确处理，不静默保留旧值。

**测试设计：** 同标签页A→B→Back、清除后复制的端到端状态比较，至少包含两个仓和质量页。

### UAR-009：分享链接保留实际分析范围

**问题与影响：** E05/E06。UBS from/to/branch仅与当前快照比较，不执行任意历史查询；Triton公共记录URL仅序列化sort/ps/page，趋势分支/时间窗与搜索没有完整分享能力。用户可能把同一URL当成同一分析结果。
