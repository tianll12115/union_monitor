# 社区工程能力看板：精简展示与实施验收方案

日期：2026-10-21。状态：可供实施评审的需求方案，业务实现尚未开始。本文只交付方案与规格测试，文档测试通过不等于页面改造验收通过。

## 1. 唯一目标与本次决策

看板只服务一个目标：**让使用者从真实门禁记录判断目标社区的工程反馈速度、门禁稳定性和主要瓶颈，并能定位到具体 PR / 执行。** 当前数据能反映社区 CI 工程能力的一部分；页面不据此声称已经衡量代码质量、发布能力或整个社区的综合实力。

用户已明确：左侧任务太多；“项目概览”实际是 UBSCore 九仓总览；“趋势与任务”和“PR 与批次”应合并；“数据质量”“数据与采集”“指标说明”三个独立页面直接删除；Triton 不应为了导航一致而出现没有内容的任务。本方案据此重设产品范围。

**推荐方案：左侧只有两个社区入口，主内容只有三种页面。**

| 选择 | 页面组织 | 取舍 |
|---|---|---|
| 采用：按社区进入，再下钻记录 | 左侧 UBSCore / Triton-Ascend；UBS 九仓总览→仓库工程效能；Triton 直接工程效能 | 去掉“任务平台”结构，适配多仓与单仓真实差异，保留最短诊断路径 |
| 不采用：给每个社区保留“概览/趋势/记录”菜单 | 每个社区继续拥有多个任务入口 | UBS 同页重复、Triton 单仓概览冗余；菜单名称变化不能解决信息分散 |
| 不采用：全部社区拼成一张全局总览 | 一个首页混放两社区 KPI 和记录 | 样本单位、时间窗与门禁规则不同，难以解释，也会扩大首页 |

最终展示结构：

```text
左侧（仅两个入口）                 主内容
UBSCore ───────────────────────→ UBSCore 总览：E2E摘要 + 九仓对比表
                                  └─ 点仓库 → 仓库工程效能：趋势 + 记录
Triton-Ascend ──────────────────→ Triton 工程效能：趋势 + 记录

每个工程效能页：范围 → 适用的1～2张指标卡 → 最多2张诊断图 → 1份记录列表 → 同页详情
```

**明确移除：** 全局工作台、任务栏及任务页签、重复项目选择器、独立数据质量页、独立采集页、独立指标说明页、无内容的占位任务、宣传式大标题、重复的“关注/异常/全部”多份列表。

**就地保留：** 数据覆盖截止与迟更提示、样本数、必要的排除原因、指标简短提示、来源链接。它们直接决定当前数值能否解释，放在指标/图表/记录旁；不再组成维护型页面，不展示采集调度表、运行矩阵或后台配置面板。后台质量校验、身份/来源证据、发布门禁继续保留，不向用户暴露完整运维流程。

## 2. 使用路径与页面内容

### 2.1 UBSCore 总览：九仓工程表现

默认入口为 `#projects/ubs/overview`，页面标题明确为 **UBSCore 总览**，涵盖当前配置九仓，不再叫泛化“项目概览”。展示范围和共同数据截止；某仓旧数据/失败/未覆盖时标出该仓，不以其他仓最新时间掩盖。

上方仅一张“代表门禁 E2E”卡，以P90为主值，P50与有效n为辅值。范围行说明“已观测 N 个 PR / M 次执行”“有效 E2E n/N”“纳入 x/9 仓”。PR 数量属于观测规模，不占一张能力评分卡。

下方只保留九仓对比表：仓库、观测 PR/执行数、P90/P50及有效n、成功/失败/执行中/取消数量、数据覆盖状态。默认按 P90 降序、未知最后、同值按完整仓库身份；这只是定位较慢样本的排序，不标“社区能力排名”。样本不足明显提示，不能把一个样本排在前面就宣称该仓更差。总览没有独立关注区、第二份 KPI、x86/ARM/DT 宽表或完整 PR 列表。

点击仓库名称进入该仓的工程效能页。总览不把九仓P90或平均数再平均：E2E取每PR代表值后合池计算，状态数量按完整批次身份去重汇总。取消沿项目原规则呈现，不能靠精简界面偷换原状态。

### 2.2 UBSCore 仓库工程效能：看趋势并找到最慢 PR

入口 `#projects/ubs/engineering?repository=gitcode%3Aopeneuler%2Fubs-engine`。标题为“ubs-engine · 工程效能”，页首提供“返回 UBSCore 总览”和仓库选择；全部九仓对比留在总览，仓库页不再提供含义含混的“全部仓库”选择。

主内容依次为：

1. 一行分析范围：仓库、目标分支、PR 创建时间范围、实际覆盖截止。支持快照内“近7天/近30天”和自定义范围；不得假装查询尚未采集的历史。
2. 一张“代表门禁E2E”卡，含P90/P50/n及范围/样本说明。
3. 最多两张图：按 PR 创建日的代表 E2E P50/P90 趋势；代表批次 x86/ARM/DT 的排队/执行耗时诊断图。任务必须来自同一代表批次，不跨批次补齐字段。图上注明时间依据，不能把 PR 创建日图当成当天 Jenkins 资源使用量。
4. 一份 PR 列表：PR身份/标题、PR状态、最长合格代表E2E与结果、执行次数、关键任务耗时；次要作者/SHA/全部任务在详情展开。默认一PR一行，按代表E2E降序。#1627仍只有一行，代表#7604、16.62分钟，全部9次执行在详情。
5. 点击PR展开同页详情；可选择任一执行，查看排队、执行、子任务和来源。无代表的PR保留一行并说明原因。

搜索（编号/标题/作者/SHA）、结果快速筛选、排序、分页和导出就在列表区，不另设“PR与批次”任务。“全部/失败/执行中/耗时偏长”是同一列表的筛选，不复制四份列表；UBS失败筛选定义为“存在至少一次失败执行的PR”，行上同时保留代表结果，不混淆这两个条件。

UBS“执行中”指存在任一次status=running的执行；“耗时偏长”仅按合格的代表E2E≥当前S的P90判断，不按任一次观测值或最新一次。阈值含并列，n=0时禁用并说明无有效阈值，n<5保留值但提示样本较少。Triton则按当前批次status判断失败/执行中，偏长仅匹配合格E2E样本且duration≥当前S的E2E P90；未关联PR/运行中不能冒充终态偏长样本。搜索或结果标签不能重算阈值。UBS取消沿既有状态可能属于失败子集时明确提示“其中取消n次”，不得再与失败数相加当执行总数。

### 2.3 Triton-Ascend 工程效能：同页看 E2E、NPU 与执行

入口 `#projects/triton/engineering`，单仓直接进入工作页，不经过空泛项目概览，不显示只有一个值的仓库选择器。

主内容与UBS共享层级：范围、适用指标、最多两图、一份记录、详情。Triton有两张卡：“门禁E2E”“NPU最长排队”，分别显示P90/P50及各自有效n。保留两张必要诊断图：按本次批次起点的E2E散点、NPU最长排队散点；共享同一个分支与时间范围。A3/A5等任务详情放在执行详情中，不新增并列栏目。公共记录页与原趋势页真正合并为同一内容树，不是通过切换隐藏另一块内容。

两图及摘要均从同一S按各自资格派生，点数与有效n可以不同，不要求图点数等于全部记录数。原两图各自一套状态按钮撤除，结果定位只在记录区提供一套；点选图表或筛记录只定位/高亮，保留完整分析分布。

记录实体保持“提交/重跑批次”：同PR不同SHA/attempt是不同执行，记录上明确PR、SHA、attempt和本次时间，不强行聚合成一个Triton PR E2E。筛选/点击图点后，同页列表可定位对应批次并打开详情。支持“今天（上海时间）/近6小时/近24小时/近72小时”，今天按本次批次起点截取到已覆盖截止；显示“涉及PR/执行批次”，不称为“今天新增PR”。

## 3. 最小指标字典与可信边界

全应用只保留三个有实际来源的主指标定义，不强求每社区卡片数量相同。每个指标以P90表达长尾，P50解释典型耗时；状态数量和同列表筛选帮助观察失败与执行中情况，不新增统一成功率或综合评分。瓶颈由任务图/执行详情解释。每个指标就近显示单位、n和一行口径，完整来源可从详情访问；不再通过“指标说明”导航学习。

| 指标ID/显示名 | 所属页面与粒度 | 计算、时间依据与分母 | 决策含义与边界 |
|---|---|---|---|
| K1 / 代表门禁E2E | UBS总览/单仓；每PR一个代表 | 选区PR各取最长合格、有限非负E2E，对代表集合算P90/P50；按PR创建时间选区；n/选区PR数 | 反馈长尾与典型速度；任务不跨批补齐。新增P50派生值，复用既有代表和取消规则，不改为最新/成功优先 |
| K2 / 门禁E2E | Triton；每提交/重跑批次 | 选区内符合现有E2E身份/资格的成功、失败批次，对有限非负时长算P90/P50；按本次批次起点；n/选区批次数 | 提交验证反馈速度；运行中仅作观测，不进入终态分位数，取消/未知身份按既有规则排除 |
| K3 / NPU最长排队 | 仅Triton；每批包含的NPU任务最大排队值 | 沿用现有NPU独立资格，对有限非负最长排队值算P90/P50；n/选区批次数，分别给无NPU、缺证据和其他排除数 | 验证资源等待瓶颈；未关联PR若仍有合法NPU证据可按既有NPU资格纳入，不能套用E2E的n |

三个指标均不重写原快照状态、旧CSV结果或原有资格规则。P90/P50使用线性插值位置(n−1)×q，不是SLA，不设臆造红线。取消/执行中/不完整/未知数量在范围行、列表标签或就近展开内分别可查；分母排除不能隐藏。稳定性仅作当前已观测结果的描述，失败数量少不能直接推导测试更有效。

范围注记包含已观测PR数（完整仓库+PR身份去重）、执行数（完整批次身份去重）、E2E有效样本/候选样本、实际覆盖截止。**PR数量不是工程能力分数；没有记录也不代表能力为零。** Triton的涉及PR不是新建PR；初始批次也不是完整提交事件总数。无Actions的新PR尚无独立完整枚举，本期不新加“今天新增PR”卡或为了它扩建采集系统。

规则：

- 所有耗时页面统一两位分钟，比较与分位数按原精度计算；旧CSV保持原字段和单位，导出元数据明确ms/s。任务排队和运行时长不擅自与E2E相加。
- n=0显示“无有效样本”，不显示0分钟或0%。合法0保留。n<5显示“样本较少”；这是解释提示，不是统计显著性结论或达标线。
- UBS九仓统计按真实PR/批次池计算；失败/未覆盖仓不填0，过期仓不能混成当前同窗池。Triton只有部分NPU明细缺失时，只影响NPU统计，不反过来否定合格E2E。
- 分支与时间先决定分析集合S；列表搜索/结果标签/排序/分页决定定位集合L。为保持简洁，移除原独立“完整性/触发类别”高级分析面板，相关字段在详情中查；本期列表筛选均不改变S，页内明确“下方筛选仅定位记录”。图点定位只高亮列表，不删除其他分析样本。
- 批次起点未知的记录不进入时间选区S，但同一记录区提供“时间未知(n)”就地入口；这是明确标为不计入选区统计的诊断集合，不能随质量页删除而丢失。该集合单独导出时明确时间归属未知，不冒充普通L导出。
- UBS和Triton分别分析自身窗口，禁止跨社区混算E2E、综合总分、榜单或“谁更强”结论。默认不做环比箭头；当前缺少不可变、同口径的完整前期数据，PR代表值还会被后续执行更新。趋势允许描述观察变化，不推出因果结论。
- 一期不加DORA四指标、发布频率、修复时长、测试覆盖率、首次通过率、统一成功率、人员排行榜或AI总结；没有稳定来源与必要性前不扩展。UBS生命周期只留详情，创建窗口内已合入子集有删失偏差，Triton也没有同等字段，不升为主KPI。

## 4. 交互与展示要求

左侧固定两个社区入口，选中态跟随当前社区；页面不再出现“任务”分组、工作台入口、页头项目下拉或同功能页签。UBS总览→仓库只需一次点击，Triton入口一次点击直达工作页，工作页再一次点击进入目标记录详情。

跨社区切换保留各自适用范围并写入目标URL；UBS始终先落总览，可从仓库表恢复该仓的上次范围。直接地址的显式参数优先，缺省参数取定义好的默认值，不能继承前一地址残留。浏览器前进后退恢复实际筛选、排序、页码及详情；关闭/Escape清详情参数并恢复焦点。搜索后列表计数/导出一致，KPI与趋势保持S。

页头用社区/仓库名承担标题，不再放“让每一次提交，清晰可见”大面积hero。1440px桌面首屏应看到范围、适用指标卡及诊断图标题；记录检索位于图下同页可达，提供一个“查看记录”页内锚点。手机单列排列，桌面图可并排；不为表格增加主导航。

两张图和导航器标签距容器裁切边至少8px，相邻标签间至少8px；支持320/390/768/1024/1440px与200%缩放。长耗时/跨日标签完整可读，必要时减刻度或换单位，不靠隐藏数据解决贴边。详情/记录均有键盘按钮；图中读数有可聚焦点或等价数据表，不只靠鼠标或颜色。

普通状态只占范围行的一条“数据截至…/采集于…”说明；只有迟更、部分覆盖或失败才显示紧邻内容的醒目提示。重读失败保留旧数据与原时间，不改成采集成功。提示不是新页面，不把整份运行报告、检查日志或采集计划搬入折叠面板。

## 5. 路由、代码边界与历史需求取舍

保留稳定项目ID `ubs` / `triton` 和完整仓库ID，只将展示名称改为UBSCore；不重命名底层采集项目或来源路径。规范路由只有三种：

| 规范页面 | 规范入口 | 范围 |
|---|---|---|
| UBSCore总览 | `#projects/ubs/overview` | 九仓；默认近30天PR创建队列 |
| UBS仓库工程效能 | `#projects/ubs/engineering?repository=gitcode%3Aopeneuler%2Fubs-engine` | 单仓；默认近30天PR创建队列 |
| Triton工程效能 | `#projects/triton/engineering` | 唯一仓；默认近72小时批次起点 |

旧链接兼容一次规范化，以replaceState更新地址；保留有效仓库、分支、时间依据/范围、搜索、排序、页码和PR/批次身份。旧排序键在新实体不适用时明确回退默认。质量/说明页已删除，旧链接仅显示简短“页面已精简，已返回…”提示，不能继续挂载旧页面或出现死链。

已移除的完整性/触发类别等高级条件不作为隐藏筛选继续生效，旧链接包含时提示哪些条件已移除、当前实际范围是什么，不声称完全恢复。旧PR生命周期分析条件若没有等价控件亦按同样规则处理，不静默改成结果状态。未知仓库、重复身份参数或失效详情应明确报错/不存在，不能替换为另一个对象。

| 旧入口 | 新去向 |
|---|---|
| 空hash、`#workbench`、`#ubs`、`#repositories` | UBSCore总览 |
| `#projects/ubs/overview` | 仍为UBSCore总览；即使旧地址带单仓也不把它伪装成总览，明确迁移到相应仓库工作页 |
| `#ubs/repo/{repo}`、`#repo/{repo}`、`#projects/ubs/trends`、`#projects/ubs/records`、`#overview`、`#prs` | 对应UBS仓库工程效能；未指定仓库时用明确默认ubs-engine并写入URL |
| `#triton`、`#projects/triton/overview`、`#projects/triton/trends`、`#projects/triton/records` | Triton工程效能 |
| UBS质量类、`#quality`、`#method`、`#repo/{repo}/method`、两社区quality/collection/method | 能确定仓库则回该仓工程效能，否则回所属社区入口；全局method无社区归属时回UBS总览 |

前端拆改应针对真实入口：`web/shell.js` 的FIXED_TASKS和 `web/app.js` 的renderSideNav负责生成菜单，只改HTML不能删掉菜单；UBS单仓已有图表+记录，可重排复用；Triton的renderTritonView / renderTritonRecords目前互斥，必须改为共享分析集合的合并挂载。删除qualityBadge、旧任务模板/事件、空任务分支与隐藏图表上的监听器，避免删DOM后空引用。详情/筛选/导出复用现有模型并补齐前轮已知接线问题，不引入新前端框架。
