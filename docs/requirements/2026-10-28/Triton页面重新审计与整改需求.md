## 1. 结论与审计边界

用户报告的纵轴读数错误已原样复现。真实标签是 `3308.76 → 2481.57 → 1654.38 → 827.19 → 0.00 min`，左侧裁掉高位数字后，变成用户看到的 `308.76 → 481.57 → 654.38 → 827.19 → 0`。这不是可以接受的显示精度差异，而是改变读数含义的基础功能缺陷。

更严重的是散点中心被二维防碰撞算法移动，位置不能反映真实时间与时长；窄屏尺寸切换后还出现横轴日期反向。即使样本统计的算术正确，这些图也不能作为可靠的数值读图依据。

本轮共登记 **14 项整改需求：P1 5 项、P2 8 项、P3 1 项**。其中包括已现场复现的缺陷、冻结线上实现的条件场景缺陷，以及门禁整改要求，不能说成“14 项全部在线上当前数据中复现”。本报告不是全站、全部浏览器或全部上游记录的正确性认证。

### 证据级别

- **A：线上真实浏览器**。读取实际渲染位置、操作后状态，必要时有截图；不是只检查 DOM 文本存在。
- **B：冻结真实数据独立重算 / 上游抽查**。数字可复算；上游抽查只代表被抽查记录。
- **C：冻结线上代码 + 合成输入运行**。实现缺陷可复现，但当前生产快照未必包含触发条件。
- **D：静态路径 / 公式检查**。已追踪代码和相关需求，未宣称完成浏览器现场复现。

## 3. 逐项整改需求

### TA-001：纵轴标签必须完整可读，不能裁掉高位数字

**问题与复现：** 打开完整 72 小时选区、全部分支。E2E 图前三个标签原文均宽 66.53px，文本左边界为 557.97px，而裁切父容器左边界为 563.5px，最左约 5.53px 被裁掉。第四个标签宽 60.48px，未被同样裁掉，造成可见数值从上向下反而增大。

**影响：** 用户会将数千分钟读成数百分钟，误判纵轴方向、点值和异常程度。

**定位：** 冻结 `triton-view.js` 的 `draw/drawNpu` 固定左边距 `m.l=50`，标签锚点 `m.l-8`；`style.css` 的 `.section` 为 `overflow:hidden`。只检查标签字符串单调，不能发现这个缺陷。

**整改要求：** 根据实际字体、完整格式化标签及父级裁切边界确定绘图区；保留长值，不能通过删异常值或截位缩短数字。若切换单位，必须统一标注并保持点值、提示、图例一致。

**验收标准：** TA-001-AC1：所有纵轴标签的完整包围盒均位于实际有效裁切区域内。TA-001-AC2：按实际屏幕 y 从上到下排序后，完整可见数字严格递减且零位于基线，等距网格对应等距数值。TA-001-AC3：覆盖 0、低于一分钟、四位/五位分钟及长尾真实快照；390/768/1440/2560px、字体加载后均检查。

**建议门禁（待实现）：** 浏览器渲染后检查每级实际裁切祖先和文字边界，独立核算刻度；必须让本次真实样本回放先失败。不能仅断言 `.axis` 文本存在或数量正确。

**证据：** [现场截图](evidence/browser/axis-desktop.jpg)、[原始标签](evidence/browser/axis-desktop.json)、[完整边界和点位置](evidence/browser/geometry-desktop.json)。

### TA-002：散点中心必须对应真实时间与时长

**问题与复现：** 当前真实宽屏、SVG 宽 1610px：345 个 E2E 点中 316 个位置被移动；250 个 NPU 点中 213 个被移动。`spreadPoints` 同时改变 x/y，随后直接把移动位置作为散点中心，没有真实锚点、引导线或偏移标识。

**量化例子：** PR #2742、SHA `ced0a815...`、run `40264165938` attempt 2，真实 E2E 为 19.2333min，实际点中心按该图纵轴逆算约 618.4482min；差 599.2148min。NPU PR #2004、SHA `ae31f158...`，真实排队 0.8167min，被画到约 18.6354min。此视口中最大横向偏移相当于约 158.86min。900px 离线重放的位移数量与横向误差另有不同，不能混用视口结果。

**整改要求：** 数值轴位置不可为防碰撞静默改变。允许聚类、缩放、交互展开或明确显示真实锚点的设计；不能让展开位置被误认为真实测量值。

**验收标准：** TA-002-AC1：逐个可见点独立计算真实 start_at/value 的期望位置，或从实际点中心逆算，误差不超过已声明像素容差（建议≤1px）。TA-002-AC2：覆盖密集点、完全重叠、边缘、0、运行中、取消及多屏宽；筛选前后同一真实值不能无说明跳动。TA-002-AC3：提示身份、详情、CSV 原值、真实锚点一致。

**建议门禁（待实现）：** 已知值合成样本与本次密集快照双测，预期坐标由测试独立公式求出，不能调用生产 `spreadPoints` 自证。

**证据：** [真实 DOM 逆算结果](evidence/browser/geometry-reconciliation.json)、[独立脚本](evidence/check-geometry.py)、[900px 重放](evidence/numbers/scatter-displacement.json)。

### TA-003：响应式尺寸变化后，坐标系不得失配或反向

**问题与复现：** 在完整真实快照页面由默认宽屏切到 390×844，等待后读取：两图实际宽度均 257px，但 `viewBox="0 0 35 370"`，网格和横轴起点 x=50、终点 x=13。屏幕上左侧显示 10/28，右侧显示 10/25，散点压成一列。当前证据仅证明这条尺寸切换路径，不宣称所有冷启动窄屏均同样失败。

**定位边界：** `onResize` 同步执行 `redrawAll()`，绘图读取 `clientWidth`。已证实绘图保存宽度与最终布局宽度失配；为何该次读取为 35px，仍需实现阶段追踪，不能仅凭推测归因于字体或动画。

**验收标准：** TA-003-AC1：初次窄屏、宽→窄、窄→宽、侧栏断点及容器尺寸变化后，最终 SVG 的 viewBox 与实际绘图尺寸一致。TA-003-AC2：有效 plotWidth>0，x(start)<x(end)，屏幕日期由左到右递增。TA-003-AC3：变化期间不能永久保留临时尺寸；两图与导航器同步重算，点值仍满足 TA-002。

**建议门禁（待实现）：** 不是只用 `page.setViewportSize` 后检查横向无溢出；还要检查稳定布局后的 viewBox、端点及全部点映射。保留实际失败切换回放。

**证据：** [窄屏截图](evidence/browser/mobile-resize.jpg)、[尺寸及刻度](evidence/browser/mobile.json)、[viewBox 与反向横轴](evidence/browser/mobile-mapping.json)。

### TA-004：批次分组必须与“一次触发 E2E”的定义一致

**问题与复现：** 页面称每个点为一次提交或一次手动重跑触发。PR #2628、SHA `aa410d7` 的 initial 批次却包括 Auto labeling run `40158843097`（10/25 11:36:34→11:36:47）与另一个 run `40168782436`（14:21:09→14:21:28），两者均 attempt 1。它们与首轮 review 被合并显示 E2E 164.90min。首轮已见检查跨度为 3min51s，但缺少完整触发关联证据，不能直接认定该值就是唯一正确替代值。

**扩展证据：** PR #2665、SHA `5e712b2` 包含相隔约 24h12m 的两个首次 Restricted Files Labeler run。65 个合格批次有重复同名 workflow；其中 34 个出现前者完成后超过 5min 再发起同名 workflow。这个统计用于定位语义风险，不等于证明每一项都必然应拆分。

**整改要求：** 使用可审计的触发/事件关联依据定义批次。若只能按 PR+SHA 汇总观察跨度，应明确如此命名并披露跨触发聚合，不得宣称已还原单次门禁；不能凭任意时间阈值伪造唯一分组。

**验收标准：** TA-004-AC1：同 PR/SHA 的代码提交、标签/标题变更、workflow 新 run、原 run attempt 重跑分别建模。TA-004-AC2：每一批次可解释成员归属及起终点，未知归属明确标记。TA-004-AC3：标题、点、KPI、详情、CSV 使用相同批次定义，重新核算受影响指标并保留前后差异。

**建议门禁（待实现）：** 同 SHA 相隔数小时和一天的新 attempt 1 run 不能仅凭 SHA 合并；与真正 run attempt 2 配对测试。以明确触发证据作为 oracle。

**证据：** [分组明细](evidence/numbers/semantic-check.json)、[上游三条公开来源抽查](evidence/numbers/upstream-probe.json)、[完整数字结论](evidence/numbers/findings.json)。

### TA-012：详情保留精确源值及单位

**问题：** 统一详情的 E2E、等待、执行使用两位分钟，未提供可核验的精确秒/源单位字段。7 秒只读到 0.12min；CSV 保留秒并不能代替详情自身的精确证据。这与现有本地 UDR-006“详情保留精确值、来源单位”的要求不符。部分 E2E 可由起终点自行相减，也不代表所有任务等待值都已直接提供。

**验收标准：** TA-012-AC1：详情同时提供分析显示值、源精确值及单位；缺失不能补零。TA-012-AC2：覆盖合法0、100ms、600ms、7s、null，图点/详情/CSV 同源。TA-012-AC3：精度和近似来源清楚，不以显示舍入改变计算。

**证据：** 冻结 `app.js:67`、`triton-view.js:527-544`；仓库只读参考 `docs/requirements/2026-10-12-unified-dashboard-audit-requirements.md` 的 UDR-006。

### TA-013：参考线需要可识别的名称、范围和语义

**问题：** 两图存在 `p90-line` 和 `median-line`，图例仅列成功/失败/取消/执行中，曲线没有可见名称或可访问说明。E2E 图内失败筛选后 P90=40.42min，而页级耗时偏长阈值为36.99min，用户不能从无标识参考线确定它表示哪个统计范围。没有据此认定这两个数值本身应相等。

**验收标准：** TA-013-AC1：标明图内 P90 和六小时桶中位数线的名称、样本与作用范围，不能冒充 SLA。TA-013-AC2：图内过滤变化后说明与线的位置同步；页级阈值和图内参考值可区分。TA-013-AC3：不依赖颜色唯一识别。

**证据：** [桌面截图](evidence/browser/axis-desktop.jpg)、[失败过滤现场结果](evidence/browser/failure-filter.json)、冻结 `triton-view.js:372-382,426-436`。

### TA-014：门禁必须证明结果正确，而不只是执行了测试

**既有漏检证据：** 强制散点旅程覆盖点击、身份文字、统计、路由和弹窗宽度，没有验证纵轴完整显示、真实数据到像素的逆映射。REQ-031 主要关注横轴标签。散点 fixture 仅三个稀疏点（0/60/600s），没有覆盖真实 345 批次密集长尾。重叠 UT 反而要求点移位，却没有限制数值失真。Escape 用例只看隐藏，没有检查 batch URL。覆盖率与必跑 ID 能保证执行，不能保证这些判断存在或正确。

**整改要求：** 以本轮 TA-001~013 的独立结果断言补全矩阵；保留全量 UT、浏览器套件和严格新增行覆盖率，不用增加测试数掩盖缺少关键 oracle。

**验收标准：** TA-014-AC1：在修复前的冻结实现上，本轮轴裁切、点位和深链接回归必须失败；修复后全部通过。TA-014-AC2：加入定向变异验证：裁掉高位标签、逆转轴、把0移顶、错误单位换算、静默平移点、NPU误用E2E、固定身份被悬浮覆盖、Escape残留URL。每个变异都须被对应断言拦截。TA-014-AC3：审查记录明确数据、状态、视口和断言覆盖，禁止仅用“全绿/覆盖率达标/文字存在”宣称整页可信。TA-014-AC4：语义未定的 TA-004 先确定定义和证据，不让错误的聚合成为测试预期。

**建议门禁（待实现）：** 全量 UT + 实际浏览器几何/状态断言 + 现实密集快照重放 + 独立算术 oracle + 有界定向变异检查。测试基准计算不得复用待测生产 formatter、轴或偏移函数。

**证据：** [测试空洞及源码位置分析](evidence/contracts/contracts-findings.md)。这些是未来验收要求，本轮没有修改门禁或提交代码。
